# Техническое задание: «Си — море моего мира»

Версия: 1.1. Дата: 9 октября 2026 года. Правки после экспертного разбора перечислены в разделе 20.

## 1. Назначение и обязательность решений

Создать персональный русскоязычный веб-планировщик тренировок. Он помогает одному пользователю планировать любую неделю, отмечать занятия, видеть цели и сравнивать нагрузку. Девиз: «Двигаться в своём ритме».

Внешний образ определяется `concept.md`, функциональное поведение — этим ТЗ. При расхождениях приоритет имеет это ТЗ, поскольку оно учитывает последние ответы пользователя. Все решения ниже обязательны для первой версии; дополнительные функции по инициативе разработчика не добавлять.

### 1.1. Решения после уточнений

- Единственный пользователь — владелица браузера. Регистрации, аккаунтов, ролей администратора и совместного доступа нет.
- Поля занятия: тип, дата, время, плановая длительность, заметка. Отдельного названия, видео, ссылки, места, дневника, самочувствия и фактической длительности нет.
- Минуты выполненных занятий считаются по их плановой длительности.
- Пересекающиеся занятия запрещены. Несколько последовательных занятий в один день разрешены: ответ пользователя трактуется как запрет занятий одновременно, поскольку вопрос касался одного времени.
- Прошлые занятия можно добавлять, изменять и отмечать. Будущие можно планировать; отметки выполнения и пропуска становятся доступны в их календарную дату.
- Копирование занятия на другую дату разрешено.
- Серия имеет явную дату окончания и горизонт не больше двух календарных лет от начала её сегмента. При создании можно явно исключить конфликтующие даты, сохранив запрет пересечений.
- Типы можно создавать, переименовывать, оформлять, архивировать и возвращать из архива.
- Цели задаются отдельно для каждой недели. Ни автоматического переноса, ни кнопки копирования целей нет.
- Есть поиск, фильтры и сравнение четырёх недель.
- Напоминание появляется однократно за 15 минут. Интервал не настраивается.

### 1.2. Решения по оставшимся деталям

Пользователь не уточнил последние вопросы об импорте и дополнительных инструментах. Сохранить экспорт и восстановление с полной заменой данных из `concept.md`. Печать, таймер, отдельные дни отдыха, списки упражнений, месячная статистика и статистика за всё время в первую версию не входят. Цитату и напоминания можно отключить отдельными переключателями.

## 2. Поставка и ограничения

Рабочая страница состоит строго из `index.html`, `style.css`, `app.js`. `concept.md` и `tz.md` — документация, не часть исполняемой страницы.

- Открытие двойным щелчком по `index.html` в актуальном Microsoft Edge или Google Chrome на Windows.
- В поставке HTML подключает CSS относительным путём и обычный JS через `defer`. Итоговый `app.js` — самодостаточный классический скрипт без runtime-импортов, `type="module"`, `fetch` локальных файлов и обязательного сервера.
- На этапе разработки разрешены модульные исходники, TypeScript и сборщик, если это помогает проверять код. Собрать их в три указанных файла без дополнительных чанков, картинок, карт исходников или внешних зависимостей. Исходники и инструменты разработки не входят в поставку; пользователь не запускает npm или сборку. Обычный JS без сборщика также допустим.
- Никаких внешних API, CDN, аналитики, сетевых шрифтов и облачного хранения. Все основные действия доступны без интернета.
- Хранение — `localStorage`, один документ JSON с версией схемы.
- Абстрактные растровые изображения встроить в HTML как `data:image/webp;base64,...` или `data:image/png;base64,...`; не хранить их копии в `localStorage`.
- Иконки действий — локальные встроенные SVG из Lucide с доступными подписями. SVG допустимы для интерфейсных значков, иллюстрации тренировок должны быть растровыми.
- Нет загрузки пользовательских изображений, браузерных push-уведомлений, звука, фоновых служб и синхронизации устройств.
- Нельзя гарантировать одинаковое поведение `localStorage` для `file://` во всех браузерах. Обязательно проверить прямое открытие в Edge и Chrome, а при недоступности хранилища включать описанный ниже режим несохранённых данных.

## 3. Пользователь и перечень возможностей

| Участник | Что может сделать |
| --- | --- |
| Единственный пользователь | Выбирать дату и неделю; создавать, изменять, переносить, копировать и удалять занятия; менять их статус; создавать и менять повторения; управлять типами; задавать цели; искать занятия; просматривать историю и статистику; отключать поддержку; экспортировать и восстанавливать данные. |
| Приложение | Сохранять изменения; рассчитывать повторения, конфликты, цели и статистику; выделять сегодня; показывать ежедневную фразу и своевременное напоминание; сообщать об ошибках ввода и хранения. |

Чужих данных, разграничения прав и авторизации нет. История — сохранённое расписание прошлых недель, а не журнал действий пользователя.

## 4. Первый запуск и навигация

1. Прочитать и проверить сохранённые данные. Если ключ отсутствует, создать пустое расписание, четыре исходных типа и настройки по умолчанию.
2. Не заполнять расписание демонстрационными занятиями и не создавать цели автоматически.
3. Показать неделю текущей локальной даты компьютера, с понедельника по воскресенье.
4. После каждого полного открытия снова показывать текущую неделю. Выбранная неделя, поиск, фильтры и открытые формы — временное состояние интерфейса.
5. Стрелки меняют неделю на семь дней. Выбор любой поддерживаемой даты открывает содержащую её неделю. «Сегодня» возвращает текущую неделю и выделяет текущий день.

Поддерживаемые даты занятий: с `1900-01-01` по `9999-12-31`. У границ диапазона дни вне диапазона недоступны для добавления; переход за границу заблокирован. Заголовок всегда показывает полный диапазон недели и годы, если неделя пересекает год.

При смене дня в открытой странице обновить выделение, доступность статусов и цитату. Для этого допустим отдельный таймер до ближайшей локальной полуночи; также проверять дату при открытии и возвращении фокуса/видимости. Этот таймер не относится к таймеру напоминаний. Не переключать автоматически неделю, выбранную пользователем.

## 5. Структура интерфейса

### 5.1. Основной экран

- Название «Си — море моего мира» и девиз в верхней части первого экрана.
- Панель: предыдущая неделя, следующая неделя, диапазон дат, календарь выбора даты, «Сегодня», плюс добавления.
- Строка поиска и два фильтра: тип и статус; компактное действие сброса.
- Основное расписание из семи дней, рядом или непосредственно ниже — цели и статистика.
- В статистике переключатель «Неделя / 4 недели».
- Короткая цитата отдельной строкой, без большого приветственного экрана.
- Иконка настроек открывает управление типами, переключатели поддержки и резервные копии.

День содержит дату, название дня недели, выделение сегодня и плюс. Занятия с временем сортировать по возрастанию времени, затем по стабильному ID. Занятия без времени идут последними и сортируются по ID. Занятие показывает иллюстрацию, тип, время либо «Без времени», длительность, статус и сокращённую заметку. Полная заметка доступна в форме просмотра/редактирования.

У занятия доступны: отметить выполненным или вернуть в план, открыть редактирование, повторить, удалить. Статус «Пропущено» выбирается в форме. Действия с будущими статусами недоступны и имеют пояснение «Доступно в день занятия».

Состояния пустоты различать: нет занятий в неделе; нет занятий в дне; нет совпадений поиска/фильтра; цель не задана. Для отсутствия совпадений предложить сброс фильтров, а не создание новой тренировки.

### 5.2. Формы и диалоги

Форма занятия — модальный диалог. Отдельные компактные диалоги: область изменения серии, подтверждение удаления, цели недели, управление типами, настройки/данные и подтверждение импорта.

Форма открывается с фокусом на первом поле, удерживает фокус внутри и возвращает его кнопке открытия. Escape закрывает форму; если были изменения, сначала спросить «Закрыть без сохранения?». Щелчок по фону не закрывает форму. Основные команды — «Сохранить» и «Отмена». Ошибки появляются рядом с полями; введённое не теряется.

### 6.1. Исходные типы и изображения

| ID | Название | Цвет | ID изображения и характер |
| --- | --- | --- | --- |
| `strength` | Силовые | `#F0B2A6` | `strength`: устойчивые формы, восходящие линии, коралл и морская зелень. |
| `pilates` | Пилатес | `#B8D5BB` | `pilates`: вытянутые ленты, баланс, шалфей и светлая бирюза. |
| `tribal` | Танцы — Трайбл | `#C9B9DD` | `tribal`: ритмичные переплетения, абстрактный орнамент, сирень и мягкий розовый. |
| `yoga` | Йога и медитация | `#B5D8EB` | `yoga`: горизонт, волнообразные мазки, голубой и морская зелень. |

Все изображения выполнить в едином спокойном Wellness-стиле с акварельной или бумажной фактурой. Без фотографий, буквальных спортивных поз, светящихся шаров, размытого фона и агрессивной спортивной символики. Йога и медитация — один тип; пользователь может самостоятельно создать отдельный тип медитации.

| --- | --- | --- |

| `running` | Бег | Коралловые прерывистые мазки с ощущением движения. |
| `walking` | Прогулка | Спокойный зелёный извилистый путь. |
| `cycling` | Велосипед | Связанные дуги и ритмичные голубые штрихи. |
| `stretching` | Растяжка | Раскрывающиеся сиреневые ленты. |

Эти подписи обозначают мотивы галереи, а не создают дополнительные типы автоматически. Любому типу можно назначить любое из 12 изображений. Каждая миниатюра имеет устойчивое соотношение сторон 3:2; изображения не заменяются одними иконками. Суммарный размер встроенных изображений до кодирования base64 — не больше 1.5 МиБ.

### 6.2. Управление

- Новый тип: название от 1 до 60 символов после обрезки пробелов, цвет из палитры, одно из 12 встроенных изображений. Пользовательские типы могут повторно использовать изображения.
- Дополнительные цвета палитры: `#B9DAD5`, `#E5BED0`, `#D8DFA8`, `#BFCDE8`. Произвольного выбора HEX нет.
- Названия должны быть уникальными среди всех типов, включая архивные: сравнение без учёта регистра, с обрезкой краевых и схлопыванием повторных пробелов, с эквивалентностью «ё»/«е». Использовать один общий помощник нормализации для поиска и проверки названий; сами имена хранить с пользовательским написанием. ID с именами не сравнивать: их уникальность проверяется точно, без нормализации.
- Все типы, включая исходные, можно менять и архивировать. Физического удаления типов нет.
- Переименование и оформление сразу меняют отображение всех связанных занятий и статистики, включая историю. Связь хранится по ID.
- Архивирование не удаляет занятия, повторения и цели. Существующие серии продолжаются. Тип недоступен для нового занятия, новой серии, копии занятия и новой цели по типу.
- Редактировать существующее занятие с архивным типом можно, сохраняя этот тип; сменить его можно только на активный. Изменение существующей серии без смены архивного типа разрешено.
- В фильтре архивные типы остаются с пометкой «в архиве». Есть список архива и действие «Восстановить».
- Если все типы архивированы, форма добавления предлагает создать или восстановить тип и блокирует сохранение до выбора активного типа.

## 7. Занятие: поля и проверки

| Поле | Обязательность | Правило |
| --- | --- | --- |
| Тип | Обязательно | Существующий активный тип для нового занятия. |
| Дата | Обязательно | Реальная календарная дата в поддерживаемом диапазоне. |
| Время | Необязательно | Ровно пять символов `HH:mm` с ведущими нулями; проверка по выражению ниже. Пустое значение хранить как `null`. `9:00`, секунды и `24:00` недопустимы. |
| Длительность | Обязательно | Целое число от 1 до 1440 минут, начальное значение 45. |
| Заметка | Необязательно | До 2000 символов, простой текст с переносами строк; убрать только краевые пробелы. |
| Статус | Обязательно | `planned`, `done`, `skipped`; новое занятие создаётся как `planned`. |

Регулярное выражение валидации непустого времени: `^([01]\d|2[0-3]):[0-5]\d$`.

Название занятия в интерфейсе — текущее название его типа. Отдельного поля названия в UI и данных нет. Заметки не превращать в HTML или кликабельные ссылки.

Если время задано, занятие должно полностью помещаться в календарный день: начало в минутах плюс длительность не больше 1440. Окончание ровно в полночь допустимо, переход через полночь — ошибка.

Глобальный плюс открывает форму на сегодня, если выбрана текущая неделя, иначе на понедельник выбранной недели. Плюс дня подставляет дату этого дня. Начальный тип — первый активный в порядке списка, время пустое, заметка пустая.

### 7.1. Сохранение и изменение

Все проверки выполняются до изменения рабочего состояния. При успехе изменение сразу видно в расписании, целях и статистике, после чего сохраняется одним документом. Двойное нажатие «Сохранить» не создаёт дубликат.

Для одиночного занятия можно изменить любые поля. Изменение даты — перенос; ID сохраняется. «Повторить» открывает форму с копией типа, времени, длительности и заметки; дата по умолчанию — следующий день в диапазоне, статус — `planned`, повторение выключено. Исходное занятие сохраняется. Если тип архивный, копия требует выбрать активный тип.

При удалении одиночного занятия спросить «Удалить занятие?» с типом и датой. Удалённое занятие не участвует в статистике и напоминаниях. Отмена оставляет данные без изменений.

### 7.2. Статусы

- `planned` — «Запланировано», `done` — «Выполнено», `skipped` — «Пропущено».
- В текущую дату и за прошлые даты разрешены любые переходы между статусами.
- На будущей дате пользователь может сохранить только `planned`. Перенос выполненного или пропущенного занятия в будущее предлагает сбросить статус в `planned`; без подтверждения перенос не сохранять.
- Прошедшая дата не меняет статус автоматически.
- Быстрая отметка выполнения переключает `planned` или `skipped` в `done`, а `done` — в `planned`. Она относится только к одному занятию, даже в серии.
- Минуты берутся из текущей плановой длительности. Её изменение у выполненного занятия сразу меняет статистику и прогресс.

### 7.3. Конфликты времени

Проверять пересечения по всему расписанию, независимо от открытой недели, поиска и фильтров. Проверке подлежат одиночные занятия и все действующие экземпляры серий.

- Только занятия с заданным временем и статусом `planned` или `done` занимают время. `skipped` и удалённые экземпляры не занимают его.
- Два занятия конфликтуют, если имеют одну фактическую дату и `startA < endB && startB < endA`. Интервалы полуоткрытые; 10:00–11:00 и 11:00–12:00 допустимы.
- У занятий без времени нельзя определить пересечение; они разрешены, в том числе несколько в день. Не запрещать весь день из-за пустого времени.
- При редактировании исключить из проверки заменяемую версию занятия. Смена `skipped` на `planned` или `done` снова требует проверки.
- Конфликт блокирует изменение одиночного занятия и существующей серии без частичного сохранения. Показать дату, тип и время конфликтующего занятия; при нескольких конфликтах показать список по датам. Для создания новой серии действует отдельный подтверждаемый сценарий исключения дат из раздела 8.5. Проверки полей и ошибки импорта нельзя обходить этим сценарием.
- Пример ошибки: «В это время уже запланирован Пилатес: 10:00–11:00. Выбери другое время».

## 8. Повторяющиеся занятия

### 8.1. Создание и генерация

В форме есть переключатель «Повторять». При включении доступны дни недели, интервал от 1 до 12 недель и обязательная последняя дата повторения. По умолчанию выбран день исходной даты, интервал 1 и окончание через один календарный год от начала. Требуется хотя бы один день. Последняя дата не раньше даты начала, не позже начала плюс два календарных года и включается в расписание.

Горизонт отсчитывается от выбранного начала сегмента, а не от сегодняшнего дня: пользователь может планировать произвольную будущую неделю. При прибавлении года сохранять месяц и день; 29 февраля в невисокосном целевом году заменить на 28 февраля. Если целевой год вышел за поддерживаемый диапазон, ограничить последнюю дату `9999-12-31`. Новая серия начинается с одного сегмента; каждый последующий сегмент при изменении следующих занятий имеет тот же максимум в два года от собственного начала. Автоматического продления нет: продление выполняется явным изменением будущего сегмента или созданием новой серии.

При смене начала пересчитать окончание по умолчанию только если пользователь ещё не менял его вручную. Ручное окончание не исправлять молча; если оно вышло из разрешённого диапазона, показать ошибку.

Поле даты означает начало серии, а не обязательный первый экземпляр. Если этот день не выбран среди дней повторения, первый экземпляр появляется в ближайший подходящий день не раньше даты начала. Перед сохранением показать текстовое резюме и первую дату; если до последней даты нет ни одного экземпляра, сохранение запрещено.

Пусть `anchor` — понедельник недели начала сегмента серии. Экземпляр на дате `d` существует, если одновременно:

1. `d` находится в пределах сегмента и не позже обязательной последней даты повторений.
2. День недели `d` входит в выбранный список.
3. Количество календарных недель между `anchor` и понедельником недели `d` — неотрицательное целое, кратное интервалу повторения.

Бессрочных сегментов нет. Рассчитывать экземпляры для нужного периода, не сохранять каждый из них отдельной записью. Переходы по неделям, перезагрузка и поиск не создают новых записей и дубликатов.

### 8.2. Экземпляры и исключения

У экземпляра стабильный ID: `seriesId:scheduledDate`, где `scheduledDate` — дата по правилу серии до индивидуального переноса. Фактическая дата может отличаться. Индивидуальная отметка, перенос, изменение полей и удаление сохраняются отдельным исключением с этим ключом.

Для редактирования и удаления экземпляра предложить две области: «Только это занятие» и «Это и следующие по серии». Вторая область доступна только когда исходная и фактическая даты выбранного экземпляра не раньше сегодня. Для прошлого экземпляра доступно только индивидуальное изменение; рядом пояснение «Прошлые занятия меняются отдельно, чтобы сохранить историю». Для смены статуса выбор области не нужен: всегда только один экземпляр.

- «Только это»: разрешено изменить тип, фактическую дату, время, длительность, заметку и статус. Правило повторений недоступно. Изменение действует исключительно на этот экземпляр.
- Индивидуальное удаление оставляет исключение `deleted`, поэтому занятие не появляется снова после перезагрузки.
- «Повторить» для экземпляра создаёт независимое одиночное занятие, не новую серию.
- Индивидуальные изменения имеют приоритет над шаблоном серии.

### 8.3. Изменение следующих занятий

Область «Это и следующие» определяется исходной `scheduledDate`, а не фактической датой перенесённого экземпляра. В диалоге явно показать дату начала действия.

Серия хранит последовательные непересекающиеся сегменты правил. При изменении с даты `D`:

1. Сохранить правила и экземпляры с исходными датами раньше `D`.
2. Завершить прежний сегмент датой `D - 1 день`; удалить или обрезать более поздние сегменты.
3. Создать новый сегмент с началом `D`, новым набором дней, интервалом, шаблоном и обязательной последней датой не позже `D` плюс два календарных года. В форме подставить прежнее окончание сегмента, которое можно явно изменить. Отсчёт интервала начинается с понедельника недели `D`.
4. В этой форме дату начала `D` не редактировать; перенос одного занятия выполняется через «Только это». Новый набор дней может означать, что в сам день `D` экземпляра больше нет.
5. Исключения будущих экземпляров на датах, которые остаются в новом расписании, сохранить с их индивидуальными значениями. Перед подтверждением показать их количество и пояснение, что они сохраняют личные изменения.
6. Исключения на исходных датах, которых больше нет в расписании, удалить вместе с отменёнными экземплярами. Если такое исключение индивидуально перенесено на фактическую дату раньше сегодня, предварительно преобразовать его в одиночное занятие с текущими значениями, чтобы не потерять историю. Затем удалить исходное исключение: его дата уже не генерируется новым правилом. Сохраняющиеся в новом расписании исключения с прошедшей фактической датой оставить без изменений по пункту 5. Новые прошлые экземпляры при этой операции не создаются, поскольку `D` не раньше сегодня.
7. Перед сохранением показать диапазон действия, число затрагиваемых занятий выбранной недели и число исключений, которые будут отменены.
8. Проверить конфликты итогового расписания. Сохранить изменение целиком либо отклонить целиком.

При удалении «Это и следующие» обрезать серию перед `D`, убрать будущие исключения и сохранить фактически прошедшие занятия по правилу выше. Экземпляры с исходной датой раньше `D` остаются, даже если их индивидуально перенесли на более позднюю фактическую дату; это поясняется в диалоге. Пустые сегменты удалять, но идентичность оставшейся серии сохранять. Если сегментов не осталось, удалить запись серии и связанные исключения; предварительно сохранить перенесённую прошлую историю одиночными занятиями.

Если прошлые даты превращаются в одиночные занятия, перенести их отметку показанного напоминания на новые ID; не создавать повторное напоминание. При копировании занятие получает новый ID и собственное напоминание.

### 8.4. Проверка конфликтов повторений

Проверить каждый фактический экземпляр изменяемого конечного сегмента до его даты окончания, включая исключения. Проверка только открытой недели или ближайшего месяца запрещена. Допустим простой перебор дат сегмента, максимум около 732 календарных дней, с группировкой существующих занятий по фактической дате. Расчёт периодов и НОД для бессрочного будущего не требуется.

Учитывать удалённые экземпляры, статусы и фактические даты переносов, даже если перенос находится за пределами исходного периода. При изменении нескольких сегментов или импорте проверять все сегменты, а не только последний. Построить итоговое расписание в памяти, сгруппировать по датам и проверять интервалы без учёта заменяемых старых версий. Для новой серии собрать все конфликтующие исходные даты, а не остановиться на первой; показать их по разделу 8.5.

### 8.5. Конфликты при создании новой серии

Если у новой серии есть конфликты, не сохранять её сразу. Показать диалог с числом конфликтующих дат, списком дат и существующих занятий с типом и временем. Список полностью доступен с прокруткой. Показать также, сколько занятий останется при исключении этих дат.

Доступны три команды:

1. «Вернуться к форме» — сохранить введённые поля и позволить поменять время или дни.
2. «Создать без конфликтующих дат» — только после явного выбора создать серию и исключения `deleted` для всех её конфликтующих исходных дат одной операцией. Существующие занятия не изменять. Исключённые даты не считать статусом `skipped` и не учитывать в статистике.
3. «Отмена» — ничего не создавать, закрыть диалог конфликтов и вернуться к заполненной форме.

Если свободных экземпляров нет, вторую команду отключить и показать «Нет свободных дат для этой серии». Перед окончательным сохранением повторно проверить актуальность данных и конфликтов; если они изменились, обновить список и потребовать новый явный выбор. После создания показать короткий результат «Серия создана; исключено дат: N», без поздравления.

Этот сценарий относится только к созданию новой серии. При редактировании существующей серии нельзя автоматически удалять индивидуально изменённые или выполненные занятия ради устранения конфликтов: показать все конфликты и вернуть пользователя к форме. Индивидуальное удаление и другие исключения сохраняются обычным способом.

## 9. Недельные цели

Цель привязана к дате понедельника конкретной недели. В форме можно независимо задать:

- Общее количество занятий: целое от 1 до 99.
- Общее число минут: целое от 1 до 10080.
- Количество занятий по отдельным активным типам: целое от 1 до 99, одна строка на тип.

Пустое поле означает отсутствие соответствующей цели, а не ноль. Все пустые поля и отсутствие строк по типам удаляют цель недели после сохранения. Добавить, изменить или удалить цель можно в прошлой, текущей и будущей неделе. Цели других недель не меняются; переноса нет.

Прогресс учитывает только `done` по фактической дате. Для количества использовать число занятий, для минут — сумму плановых длительностей выполненных занятий. Цель по типу учитывает только этот тип.

Показывать «выполнено / цель» и отдельно потенциальный объём: `done + planned`, исключая `skipped`. Полоса прогресса ограничена 100%, фактические числа могут превышать цель. При цели 3 и четырёх выполненных показывать «4 / 3», без поздравлений. Цели и их показатели не зависят от фильтров и поиска.

Противоречивые личные цели, например общее количество меньше суммы целей по типам, не запрещать: цели независимы. Архивирование типа сохраняет ранее заданную цель по нему. Удаление и перенос занятия немедленно пересчитывают обе затронутые недели.

## 10. Статистика

### 10.1. Выбранная неделя

Показывать отдельные количества `planned`, `done`, `skipped`, минуты выполненных занятий, прогресс целей и распределение выполненных занятий по типам. Количество `planned` — только занятия со статусом `planned`, а не общее количество всех записей.

Распределение: для каждого типа с выполненными занятиями показать число, минуты и долю от общего количества выполненных. Доля = `countByType / doneCount * 100`, для подписи округлить до целого; из-за округления сумма подписей может отличаться от 100%. При нуле выполненных показать пустое состояние без деления на ноль.

### 10.2. Сравнение четырёх недель

Период — выбранная неделя и три предыдущие, в хронологическом порядке. Таблица и компактные горизонтальные столбцы показывают за каждую неделю количество выполненных занятий и сумму их плановых минут. Недели без занятий остаются в сравнении с нулями. Будущие недели тоже показываются, если они попали в выбранный период.

Статистика считается по всем занятиям периода независимо от фильтров, заметок, архивности типов и открытого результата поиска. У перенесённого экземпляра используется фактическая дата, у удалённого — нет вклада. Не хранить готовые суммы в `localStorage`, вычислять из данных.

Пример: за неделю выполнены Силовые 45 минут и Йога 30 минут, запланирован Пилатес 60 минут, пропущен Трайбл 40 минут. Показатели: `planned=1`, `done=2`, `skipped=1`, выполнено 75 минут, потенциальный объём 3 занятия и 135 минут.

## 11. Поиск, фильтры и история

### 11.1. Фильтры расписания

Фильтр типа: «Все виды» плюс все активные и архивные типы. Фильтр статуса: «Все статусы», «Запланировано», «Выполнено», «Пропущено». Фильтры применяются совместно к занятиям выбранной недели. Дни недели и плюсы остаются видимыми. «Сбросить» очищает оба фильтра и поисковую строку.

### 11.2. Поиск

Поиск по текущему названию типа и заметке, без учёта регистра, с эквивалентностью «ё»/«е», по вхождению всей введённой строки после обрезки пробелов. Запрос максимум 200 символов. Не добавлять поиск по отдельному названию занятия, поскольку такого поля нет.

Пустой запрос — обычное недельное расписание. Непустой запрос открывает вместо сетки список результатов с переключателем области «Эта неделя / История». По умолчанию «Эта неделя». Тип и статус продолжают фильтровать результаты.

«История» ищет по всем занятиям с фактической датой не позже сегодня, включая сегодняшние, и всем соответствующим экземплярам серий. Будущие экземпляры в глобальную историю не включаются. Нет ограничения «только посещённые недели»: ранее не открывавшиеся недели также участвуют.

Результаты сортировать по фактической дате от новых к старым, затем по времени, занятия без времени после временных, затем по ID. Показывать 50 результатов за раз с «Показать ещё», если есть следующие. Не создавать сохранённых экземпляров ради поиска. Для длительных историй генерация должна происходить частями без зависания страницы; нового запроса достаточно, чтобы отменить предыдущий расчёт.

Каждый результат содержит дату, тип, время, минуты, статус и заметку. Доступны те же действия, что в расписании, и «Открыть неделю»: перейти к неделе фактической даты, очистить поиск и фильтры, выделить занятие. Смена недели или «Сегодня» также очищает поисковый запрос, но сохраняет выбранные фильтры, пока пользователь не сбросит их.

## 12. Цитаты и напоминания

### 12.1. Цитата

Встроить ровно эти три авторские фразы, без внешних авторов:

1. «Двигаться можно мягко. Главное — слышать себя».
2. «Сегодня достаточно одного бережного шага».
3. «У твоего ритма есть место для отдыха».

Выбор детерминированный: порядковый номер текущей локальной календарной даты по григорианскому календарю, начиная с `0001-01-01 = 0`, по модулю 3. Перезагрузка в тот же день не меняет фразу. Настройка «Показывать фразу дня» по умолчанию включена.

### 12.2. Напоминание

- По умолчанию включено; есть только переключатель включения, без выбора интервала.
- Для `planned` с временем, если до начала осталось больше нуля и не больше 15 минут, показать один ненавязчивый баннер: «Через [N] мин — [тип], [время]». `N` округляется вверх.
- Проверять при открытии, после изменений, при возвращении фокуса, `pageshow` и `visibilitychange` в видимое состояние. После проверки запланировать один `setTimeout` на ближайший момент начала окна напоминания. При изменении данных отменить прежний таймер и рассчитать новый; одновременно активен максимум один таймер напоминаний.
- На скрытой вкладке таймер напоминания отменить и баннер не показывать. При возвращении сначала проверить текущее время, затем заново запланировать событие. Постоянный опрос каждые 30 секунд не требуется.
- Для далёкого события ограничить одну задержку 24 часами и при срабатывании пересчитать расписание: нельзя передавать в `setTimeout` произвольную задержку в месяцы. В обработчике всегда повторно проверить дату, статус, настройку и отметку показа, поскольку таймер может сработать позже ожидаемого.
- Если страницу открыли за пять минут, показать напоминание сейчас. Если занятие уже началось, прошедшее напоминание не показывать.
- Напоминание не зависит от выбранной недели или фильтра: проверять ближайшие реальные занятия относительно часов компьютера.
- Занятия без времени, `done`, `skipped`, удалённые экземпляры и выключенные напоминания не вызывают баннер.
- Показанное напоминание сохраняется по стабильному ID занятия. Оно не повторяется после перезагрузки, закрытия баннера, смены статуса или индивидуального переноса этого же занятия. У копии новый ID, поэтому будет собственное напоминание.
- Если несколько занятий попали в окно, показать их в одном баннере списком и отметить каждое показанным. Запрета пересечений это не отменяет.
- Баннер доступен через `aria-live="polite"`, не забирает фокус, не скрывает навигацию и закрывается крестиком. Нет звука, всплывающего браузерного разрешения, фоновых уведомлений и повторных сигналов.
- При закрытой странице напоминаний нет. Если вкладка была приостановлена системой, точное время появления не гарантируется; проверка при возвращении обязательна.

`setTimeout` тоже может задерживаться браузером и не гарантирует точного фонового уведомления. Этот подход сокращает лишние проверки, а корректность после паузы обеспечивает повторная проверка актуального времени. Документация: [MDN о задержках таймеров и неактивных вкладках](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout).

## 13. Модель данных

Основной ключ: `seaPlanner.state.v1`. Его значение — JSON-документ следующей структуры. Поля ниже обязательны, если явно не указано `null`.

| Поле | Тип и содержание |
| --- | --- |
| `schemaVersion` | Число `1`. |
| `revision` | Неотрицательное целое, увеличивается при каждом сохранённом изменении. |
| `updatedAt` | UTC-время записи в ISO 8601. |
| `types` | Массив объектов `{id, name, color, imageId, archived}`. |
| `workouts` | Массив одиночных занятий `{id, typeId, date, time, durationMinutes, note, status}`. |
| `series` | Массив `{id, segments}`; `segments` — массив правил, описанных ниже. |
| `exceptions` | Массив `{seriesId, scheduledDate, kind, workout}`; уникальная пара `seriesId + scheduledDate`. |
| `goals` | Массив `{weekStart, countTarget, minutesTarget, typeTargets}`; одна запись на неделю. |
| `remindersShown` | Массив `{occurrenceId, shownAt}`; уникальный `occurrenceId`, `shownAt` — UTC ISO 8601. |
| `settings` | `{remindersEnabled: boolean, quotesVisible: boolean}`. |
| `backup` | `{startedDate, lastExportDate, reminderDismissedDate}`; календарные даты по разделу 15.3, последние два поля могут быть `null`. |

Сегмент серии: `{fromDate, toDate, typeId, time, durationMinutes, note, weekdays, intervalWeeks, endDate}`. `toDate` может быть `null`, `endDate` — обязательная дата от `fromDate` до `fromDate` плюс два календарных года. Обе верхние границы включительные; фактическая верхняя граница — минимальная из непустых. `weekdays` — уникальный отсортированный массив чисел от 1 (понедельник) до 7 (воскресенье). Сегменты отсортированы по `fromDate` и не пересекаются. `imageId` типов должен входить в 12 значений раздела 6.1; никаких ссылок на произвольные изображения.

Исключение: `kind` равно `override` или `deleted`. Для `override` поле `workout` — полный снимок `{typeId, date, time, durationMinutes, note, status}` без ID; для `deleted` — `null`. ID экземпляра вычисляется из серии и исходной даты. Исключение не может ссылаться на отсутствующую серию или на исходную дату, не генерируемую её сегментами; подавляющие исключения для сохранённой истории оставлять только там, где экземпляр иначе генерируется.

Цель: `weekStart` — понедельник, `countTarget` и `minutesTarget` — целое либо `null`, `typeTargets` — массив `{typeId, countTarget}` без повторяющихся типов. Если цель полностью пустая, запись удаляется.

ID исходных типов фиксированы. Новые ID типов, занятий и серий создаются локально как уникальные строки с префиксами `type-`, `workout-`, `series-`; использовать `crypto.randomUUID`, если доступен, иначе локальный генератор с проверкой уникальности. Разрешённый суффикс ID — от 1 до 100 символов `[A-Za-z0-9_-]`, без двоеточий; полные ID уникальны в документе. Не использовать имя типа или индекс массива как идентичность. Упоминания удалённых занятий в `remindersShown` допустимы и не являются ошибкой ссылки: это журнал предотвращения повторного показа, его нельзя использовать для генерации занятий.

Начальный документ: четыре исходных типа, все `archived=false`; остальные массивы пусты; обе настройки `true`; `backup.startedDate` — текущая локальная дата, остальные поля `backup` — `null`; `revision=0`. После успешной первой записи поставить `revision=1`. Не хранить производные суммы, загруженные изображения, выбранную неделю и содержимое несохранённых форм. `updatedAt` и `shownAt` формировать стандартным `Date.prototype.toISOString()`; точность искусственно не обрезать.

Пример полного документа с одним занятием и целью (даты метаданных служат только примером):

```json
{
  "schemaVersion": 1,
  "revision": 3,
  "updatedAt": "2026-10-09T09:00:00.000Z",
  "types": [
    {"id": "strength", "name": "Силовые", "color": "#F0B2A6", "imageId": "strength", "archived": false},
    {"id": "pilates", "name": "Пилатес", "color": "#B8D5BB", "imageId": "pilates", "archived": false},
    {"id": "tribal", "name": "Танцы — Трайбл", "color": "#C9B9DD", "imageId": "tribal", "archived": false},
    {"id": "yoga", "name": "Йога и медитация", "color": "#B5D8EB", "imageId": "yoga", "archived": false}
  ],
  "workouts": [
    {"id": "workout-example", "typeId": "pilates", "date": "2026-10-09", "time": "18:00", "durationMinutes": 45, "note": "Мягкая практика", "status": "planned"}
  ],
  "series": [],
  "exceptions": [],
  "goals": [
    {"weekStart": "2026-10-05", "countTarget": 3, "minutesTarget": 120, "typeTargets": [{"typeId": "pilates", "countTarget": 1}]}
  ],
  "remindersShown": [],
```

### 13.1. Даты и время

Даты занятий и границ — строки `YYYY-MM-DD` с ведущими нулями, время — строгое `HH:mm` по регулярному выражению раздела 7 или `null`. Применять одинаковые проверки к формам, сохранённым данным и импорту; не исправлять импортированное `9:00` незаметно. Не преобразовывать календарные даты занятий в UTC-моменты: смена часового пояса не должна менять день в расписании.

Для расчёта дней, понедельников, интервалов и модулей использовать отдельные календарные функции и порядковый номер даты. Проверять реальные дни месяца и високосные годы, в том числе 2000 и 2100. Избегать разбора `new Date('YYYY-MM-DD')` с последующим чтением локальных компонентов. Учитывать особое поведение JS-конструкторов для годов 0–99 при расчётах опорных дат.

Текущая дата и момент напоминания используют локальное время компьютера. При неоднозначном времени перевода часов выбрать первый локальный момент, при несуществующем времени — первый реальный локальный момент после разрыва. Это влияет на напоминание, но не на календарную дату занятия.

## 14. Сохранение и ошибки хранения

После каждого изменения данных сохранять весь проверенный документ одним `localStorage.setItem`. Нельзя отдельно записать часть серии или сначала стереть ключ. Изменение данных и расчёт производных показателей — одна операция в памяти; неуспешную запись обозначить явно.

Лимит объёма данных приложения: экспортное представление JSON с отступами 2 пробела в UTF-8 не больше 2 МиБ (`2097152` байта), компактная строка для хранения — не больше 4 МиБ по предварительной оценке `2 * serialized.length`, где `length` считает UTF-16 code units. Перед применением операции проверять оба лимита на полном кандидате, включая метаданные. Если лимит приложения превышен, не применять операцию, сохранить введённые поля и предложить скачать копию/удалить ненужные записи. Это проверка допустимого размера, а не ошибка уже выполненной записи. Одинаковые пределы обычного сохранения и импорта позволяют восстановить собственный экспорт без ручного уменьшения файла.

Размер UTF-8 файла, длина JS-строки и фактическая доступная квота — разные величины. Предварительная оценка не гарантирует запись: сохранять через `try/catch` и обрабатывать `QuotaExceededError` и `SecurityError`. Для прямого открытия файла поведение хранилища также не гарантировано. Документация: [MDN о формате localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [MDN об ограничениях хранилища](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

### 14.1. Недоступность и переполнение

При ошибке чтения, записи или переполнении:

1. Оставить рабочие данные в памяти, включая введённое изменение.
2. Показать постоянный компактный статус «Изменения не сохранены в браузере» с действиями «Скачать копию» и «Повторить сохранение».
3. Разрешить продолжать работу в памяти. Не показывать сообщение об успешном сохранении.
4. На попытке закрыть страницу с несохранёнными изменениями использовать стандартный `beforeunload`, насколько его поддерживает браузер.
5. После успешного повторного сохранения убрать предупреждение.

При недоступности хранилища на первом открытии создать начальный документ в памяти и показать тот же статус. Проверка доступности не должна удалять основной ключ.

### 14.2. Повреждённые или неизвестные данные

Если значение ключа не проходит разбор/валидацию или версия схемы не поддерживается, не перезаписывать его автоматически. Показать экран восстановления с сообщением, «Скачать исходные данные», «Восстановить из файла», «Начать заново».

«Начать заново» требует подтверждения, создаёт начальный документ и только затем заменяет основной ключ. «Скачать исходные данные» сохраняет исходную строку как текстовый файл. При неизвестной версии сообщить «Эта версия данных не поддерживается»; не выполнять неописанную миграцию.

### 14.3. Несколько вкладок

Несколько профилей не поддерживаются, но две открытые вкладки не должны молча затирать изменения. В режиме без локальных несохранённых изменений событие `storage` загружает актуальный документ и обновляет экран. При открытой изменённой форме или несохранённых данных показать «Данные изменились в другом окне» и заблокировать сохранение устаревшего состояния до выбора «Загрузить актуальные данные» или скачивания локальной копии.

Перед записью перечитать ключ и сравнить `revision` с последней прочитанной версией; при несовпадении применить ту же защиту. Не обещать транзакционную синхронизацию вкладок: `localStorage` её не предоставляет. Поддерживаемый основной сценарий — работа в одной вкладке.

## 15. Резервные копии

### 15.1. Экспорт

В настройках есть команда «Скачать данные». Скачать текущий документ в UTF-8 JSON с отступами 2 пробела, имя `sea-planner-YYYY-MM-DD.json`, дата локальная. Включить типы, серии, исключения, занятия, цели, настройки, показанные напоминания и `backup`. При несохранённых изменениях экспортировать актуальное состояние памяти, а не устаревшее значение ключа.

После формирования файла и запуска скачивания обновить `backup.lastExportDate` сегодняшней локальной датой и сохранить обычным способом. Браузер не сообщает странице, завершилось ли сохранение файла пользователем; не обещать проверку файла на диске. Если служебная отметка не помещается в лимит документа, не менять её и не отменять уже выполненный экспорт. При фактической ошибке записи оставить новую отметку в памяти и показать несохранённое состояние по разделу 14.1. Экспортный файл отражает снимок до служебной отметки скачивания; это не потеря пользовательских данных. Скачивание исходного повреждённого ключа не считать обычным экспортом.

### 15.2. Импорт

1. Пользователь выбирает локальный JSON-файл. Размер не больше 2 МиБ (`2097152` байта), проверять через `File.size`; более крупный файл отклонить до чтения и разбора.
2. Прочитать в память, проверить JSON, версию, типы полей, диапазоны, уникальность ID и ключей, ссылки на типы/серии, понедельники целей, конечные сегменты с горизонтом до двух лет, исключения и отсутствие конфликтов времени. Проверить также размеры нормализованного документа по разделу 14: файл без отступов может оказаться допустим по `File.size`, но слишком большим после подготовки экспортного представления.
3. Недостающие обязательные поля, неизвестные поля схемы, неизвестные значения перечислений, несуществующие ссылки, некорректные даты и повторы ключей — ошибка. Не обрезать и не исправлять данные незаметно.
4. Будущий `done` или `skipped` в импортируемой копии допускается: часы или часовой пояс устройства могли измениться. Сохранить статус, но при последующем редактировании действуют обычные правила даты. Изначальное несоответствие будущему времени не повод потерять историю.
5. До подтверждения показать число одиночных занятий, конечных серий, типов и недель с целями. Для истории показать диапазон фактических дат до сегодня либо «Истории пока нет». Число серий не подменять числом сгенерированных будущих экземпляров.
6. Предупредить: «Текущие данные будут заменены. Скачай копию, если хочешь их сохранить». Кнопки «Скачать текущие данные», «Заменить данные», «Отмена».
7. До подтверждения рабочие данные не изменяются. Объединения копий нет.
8. При подтверждении установить `revision` относительно текущей локальной версии и новое `updatedAt`, записать проверенный документ одним действием, затем показать текущую неделю с чистыми фильтрами.
9. Если запись импорта не удалась, сохранить прежнее рабочее состояние и ключ. Показать «Не удалось сохранить восстановленные данные»; разрешить повторную попытку. Импорт не заменяет данные только в памяти под видом успешного восстановления.

Примеры ошибок: «Файл слишком большой», «Не удалось прочитать JSON», «Версия данных не поддерживается», «Занятие ссылается на неизвестный тип», «В файле есть пересекающиеся занятия». Отмена выбора файла ничего не меняет.

### 15.3. Ненавязчивое напоминание о копии

В настройках постоянно доступна короткая подпись: «Данные хранятся только в этом браузере. Очистка данных сайта или браузера может удалить расписание». Не утверждать, что обычная очистка одного только кэша обязательно удаляет `localStorage`.

Дополнительно внутри раздела резервных копий показать сообщение «Можно скачать свежую резервную копию», если прошло не меньше 30 календарных дней от самой поздней из `backup.startedDate`, `backup.lastExportDate`, `backup.reminderDismissedDate`, игнорируя `null`. Есть «Скачать данные» и «Позже». «Позже» записывает текущую дату в `reminderDismissedDate`, после чего сообщение не показывается следующие 30 дней. Экспорт обновляет `lastExportDate` и также отодвигает сообщение.

Сообщение не всплывает на главном экране, не вызывает звук или уведомление и не добавляет второе напоминание о тренировке. Пока пользователь не открыл настройки, отдельно его не беспокоить. Проверять условие при открытии настроек и смене дня; частые таймеры не нужны. При импорте сохранить поля `backup` из файла, не назначать новую дату начала. Это подсказка о сохранности, а не автоматическая резервная копия.

## 16. Внешний вид и доступность

Палитра страницы: фон `#F6FAF9`, поверхности `#FFFFFF`, основной текст `#263F3B`, основное действие `#357E75`. Акценты типов описаны выше. Не превращать страницу в монохромную зелёную или бежевую тему. Одна светлая тема, без тёмного режима.

- Размер основного текста 16 px; подписи не меньше 13 px. Системный шрифт `Segoe UI, Arial, sans-serif`, межбуквенный интервал 0.
- Текст обычного размера с контрастом не ниже 4.5:1; границы и состояние фокуса хорошо видимы. Пастельный фон не использовать как цвет мелкого текста.
- Иконки: плюс, стрелки, календарь, карандаш, копирование, корзина, настройки, загрузка и скачивание. Кнопки инструментов — иконки с доступными названиями и подсказками при наведении/фокусе; ясные команды формы — текстовые кнопки.
- Размер области нажатия не менее 40×40 px, на узком экране 44×44 px.
- Скругление карточек занятий не больше 8 px. Разделы целей и статистики не оформлять как вложенные плавающие карточки.
- Тип определяется одновременно названием и изображением, статус — текстом и значком; одного цвета недостаточно.
- Изображения в занятиях имеют одинаковое соотношение сторон 3:2 и фиксированную ограниченную высоту, не сдвигают элементы при загрузке. Если название рядом передаёт всю информацию, `alt=""`; в самостоятельном выборе изображения дать короткую подпись.
- На ширине от 1200 px — сетка семи дней и блоки целей/статистики рядом, если минимальная ширина дня 120 px соблюдается; иначе блоки ниже. На 768–1199 px — семь дней в основной области, цели/статистика ниже. До 767 px — дни вертикально, панели переносятся на строки.
- На ширине 360 px и при масштабе 200% не должно быть горизонтальной прокрутки всей страницы, обрезанных кнопок, наложений и недоступных форм. Длинные заметки и названия переносятся.
- Плавные изменения интерфейса не дольше 200 мс; при `prefers-reduced-motion` убрать необязательные анимации.
- Доступны клавиатурная навигация, видимый фокус, связанные `label`, доступные ошибки форм и диалоги. Ошибки сохранения объявлять через `aria-live`.
- Тексты интерфейса обозначают даты, данные, команды и состояния. Не добавлять рекламные абзацы, инструкции о дизайне, объяснения клавиатурных сочетаний и вступительные экскурсии.
- Нет поздравлений, конфетти, рейтингов, штрафов, цепочек достижений и осуждающих сообщений.

## 19. Указания для реализации

Использовать семантический HTML, CSS с адаптивными раскладками и самодостаточный итоговый JavaScript. Разделить ответственность функций: календарные расчёты, валидация, вычисление экземпляров, конфликты, хранилище, расчёт статистики/целей, напоминания и отображение. Предпочтительно реализовать на обычном JS; при выборе инструментов разработки соблюдать различие исходников и трёх файлов поставки из раздела 2. Тяжёлый фреймворк для этой страницы не нужен.

Все пользовательские строки вставлять через `textContent` или эквивалентное безопасное создание DOM. Не использовать пользовательский текст в `innerHTML`, CSS, исполняемых URL или обработчиках. Встроенные изображения и SVG — доверенные статические ресурсы страницы.

Сначала реализовать и проверить календарные правила, модель конечных повторений и сохранение, затем интерфейс и визуальные активы. Любая оптимизация должна сохранять описанные результаты, особенно при изменении сегментов и индивидуальных переносах. Не расширять продукт функциями, исключёнными в разделе 1.

На текущем этапе создано только техническое задание. HTML, CSS, JS и иллюстрации ещё не создаются.

## 20. Решения по экспертным замечаниям

| Замечание | Решение | Причина и принятая правка |
| --- | --- | --- |
| Сложная проверка бессрочных повторений | Принято с уточнением | Сегмент ограничен двумя годами от выбранного начала, а не от сегодня. Конечный перебор проще проверить и не мешает выбору будущих дат. Разделы 8 и 13 согласованы. |
| Отказ создания всей серии из-за одной даты | Принято частично | Для новой серии есть список конфликтов и явное создание с удалёнными исключениями. Для изменений существующей серии автоматическое исключение не разрешено, чтобы не потерять личные изменения и историю. |
| Разработка обязательно в одном JS | Принято | Модульные исходники и сборщик допустимы при разработке. Пользователь получает три самодостаточных файла и не запускает сборку. |
| Фоновые таймеры | Принято с уточнением | Один таймер ближайшего события и проверка при возвращении. `setTimeout` тоже задерживается, поэтому точное фоновое срабатывание не обещано; максимальная задержка ограничена. |
| Копирование целей | Не принято | Пользователь прямо попросил не переносить цели. Экспертное предпочтение не отменяет это решение. |
| Только четыре картинки для любых типов | Проблема принята, решение изменено | Коллекция расширена до 12 абстрактных изображений. Замена картинок иконками не соответствует выбранному пользователем визуальному образу. |
| Напоминание о резервной копии | Принято в спокойном варианте | Подсказка раз в 30 дней внутри настроек, без нового баннера главного экрана. Добавлены служебные даты и пояснение о локальном хранении. |
| Отказ от эквивалентности «ё»/«е» для названий | Не принято | Общий помощник уже нужен для поиска; повторное применение не усложняет архитектуру и предотвращает визуально похожие дубликаты. ID всегда сравниваются точно. |
| Обрезка точности `updatedAt` | Не принято | Стандартный `toISOString()` проще и однозначнее; экономия нескольких символов в одном поле несущественна. |
| Ведущие нули времени | Принято | Строгое регулярное выражение применяется в формах, хранении и импорте; неоднозначные значения не сортируются как время. |
| Уменьшение импортируемого JSON | Принято с уточнением | Предел 2 МиБ, проверка сериализованного объёма и обработка реальной ошибки записи. Размер UTF-8 файла не равен размеру UTF-16 строки и не гарантирует доступность квоты. |

Обновлены модель данных, пример JSON, пользовательские сценарии и приёмочные проверки. `schemaVersion` остаётся 1: продукт ещё не реализован и ранее сохранённых рабочих данных этой схемы нет. Старые несовместимые черновики JSON не импортировать как готовые резервные копии.
